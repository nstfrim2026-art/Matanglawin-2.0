# Flask web app with real-time crack detection — v2 follow-up

The five blocking issues from the v1 review have been addressed: the MJPEG generator now catches `GeneratorExit` for clean disconnect handling, crack classification normalizes mask area by frame dimensions (ratio-based thresholds), the misleading "severity" label is renamed to "confidence" in both backend and frontend, documentation references `IP_CAMERA_URL` / "IP Camera" throughout, and the frontend reconnects the MJPEG stream when camera connectivity recovers. Two acknowledged items (Flask dev server, no rate limiting on `/set_source`) remain by design for a local/demo tool.

The MJPEG reconnection fires on first page load due to `cameraWasConnected` initializing as `false` (confirmed, benign — causes one redundant img src reset).

**Verdict**: APPROVED

## MJPEG reconnection edge on first load

`cameraWasConnected` initializes to `false`. On the very first successful `/status` poll where `camera_connected` is `true`, the condition `cameraConnected && !cameraWasConnected` evaluates true, resetting the img src to `/video_feed?<timestamp>`. This causes one redundant request on initial page load — the browser aborts the initial MJPEG connection and opens a new one. Initializing `cameraWasConnected = true` would eliminate the extra request, but the current behavior is harmless (first frame arrives within ~50ms either way).

## CSS class naming drift

The progress bar classes remain `.severity-row`, `.severity-bar`, `.severity-fill` in `style.css` while rendering "Confidence" in the UI. A grep for "severity" in the codebase will still return hits, which could mislead a future contributor into thinking the v1 issue wasn't fixed. A batch rename would eliminate the confusion, but it's not a functional concern.
