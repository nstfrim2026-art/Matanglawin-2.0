# Flask web app with real-time crack detection, analysis metadata, and marketing frontend

This change transforms a single-file YOLO overlay script into a full Flask web application: a background detector thread continuously reads frames from configurable video sources, runs YOLO11-seg inference with per-crack metadata extraction (classification, severity, dimensions), and exposes annotated MJPEG plus JSON APIs. The frontend is a multi-section marketing-style page with a live detection panel that polls the backend for status and analysis data. The "DroidCam" branding is renamed to "IP Camera" throughout.

Watch for: the MJPEG generator runs an unbounded busy-loop per connected client with no backpressure or client-count limit (confirmed). Crack classification thresholds are hardcoded pixel-area values that will misfire at different frame resolutions or camera distances (confirmed). The `severity` field is actually YOLO detection confidence, not a crack severity metric — naming it "severity" and presenting it as a percentage in the frontend is semantically misleading (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The inference pipeline computes per-detection metadata (mask area, contour bounding-rect dimensions, confidence) and classifies cracks into three buckets based on fixed pixel-area thresholds. These thresholds are resolution-dependent and undocumented, so they'll produce different classifications for the same physical crack at different camera distances or frame sizes.

The MJPEG stream generator allocates one infinite loop per HTTP client with a 50ms sleep, no connection cap, and no generator cleanup when the client disconnects. Under concurrent viewers this becomes a resource concern. Flask's development server (used in production here) holds a thread per streaming client.

The frontend polls `/status` (1s) and `/analysis` (1.5s) to drive a real-time analysis panel, but the `<img>` element pointing at the MJPEG stream has no reconnection logic if the backend restarts — the feed silently dies while the polling endpoints recover.

Documentation (README, DEPLOY.md) still references "DroidCam" in several places despite the code rename to "IP Camera," creating user-facing inconsistency.

## Unbounded MJPEG streaming without backpressure

The `_mjpeg_generator()` function in `app.py` is a Python generator that yields JPEG frames in an infinite `while True` loop with a fixed 50ms sleep:

```python
def _mjpeg_generator():
    boundary = b"--frame"
    while True:
        jpeg = detector.get_latest_jpeg()
        yield (boundary + b"\r\nContent-Type: image/jpeg\r\n..."
               + jpeg + b"\r\n")
        time.sleep(0.05)
```

Each client that opens `/video_feed` gets its own thread running this generator forever. There's no mechanism to detect client disconnect — when a browser tab closes, the generator continues burning CPU and holding the thread until the OS eventually raises a broken pipe on the next `yield`. With multiple concurrent viewers, this becomes a thread-leak vector. The 50ms sleep caps throughput at ~20fps per client regardless of `TARGET_FPS`, and there's no backpressure if the client can't consume frames fast enough.

A `try/except GeneratorExit` wrapper or a maximum-client counter would make it safe under concurrent use.

## Crack classification depends on absolute pixel counts

`_classify_crack()` uses hardcoded area thresholds:

```python
def _classify_crack(area_px: int) -> str:
    if area_px < 500:
        return "Hairline"
    elif area_px < 2000:
        return "Surface-Level"
    else:
        return "Structural"
```

A 640x480 webcam frame at 2 meters will produce very different mask areas than a 1920x1080 drone frame at 5 meters, for the same physical crack. The classification is presented to the operator as authoritative ("Structural") without any caveat that it's resolution-relative. Normalizing by total frame area (`area_px / (h * w)`) or accepting resolution as a parameter would make the metric stable across camera configurations.

## Confidence-as-severity misrepresentation

The metadata extraction in `annotate_frame()` assigns:

```python
severity = float(result.boxes.conf[i].cpu().numpy())
```

This is the YOLO detection confidence — "how sure the model is that this is a crack" — not a measure of structural severity. The frontend multiplies by 100 and renders it as "Severity 87%" with a colored progress bar (green/yellow/red), directly implying structural danger level. An operator seeing "Severity 92%" will read that as "this crack is dangerously severe" when it actually means "the model is very confident it sees a crack." The field should either be renamed to `confidence` throughout, or actual severity estimation logic should replace the confidence score.

## Documentation still references DroidCam

DEPLOY.md instructs users to `export DROIDCAM_URL=...` and references "DroidCam" by name. README.md similarly documents `DROIDCAM_URL` as an environment variable and mentions "DroidCam" as a camera source. The code now uses `IP_CAMERA_URL` and labels the source "IP Camera." Users following the documentation will set the wrong environment variable.

## MJPEG feed recovery gap

The live detection section embeds the stream as:

```html
<img id="videoFeed" src="/video_feed" alt="Live camera feed">
```

If the Flask server restarts, this element shows either the last frame or a broken-image icon. The JavaScript polls `/status` and `/analysis` (which fail and are caught), but there's no logic to refresh the `<img>` src to reconnect the MJPEG stream. Adding `videoFeed.src = '/video_feed?' + Date.now()` when the status poll detects a connection drop would restore the feed automatically.

## Flask development server as the production runtime

`app.py` calls `app.run(threaded=True)` with Werkzeug's development server. The Dockerfile `CMD` runs `python app.py` directly. The moment multiple MJPEG clients connect (each holding a thread for the connection lifetime), the threadpool can exhaust. Swapping to `gunicorn --threads` or a gevent worker would eliminate the constraint without changing app code.
