# LetsView window capture as a new video source (v2)

Adds a screen-capture video source (`LetsViewSource`) that grabs frames from the LetsView mirroring window on Windows, enabling the DJI Fly app to feed into the existing YOLO crack detection pipeline without camera hardware changes. The implementation follows the `VideoSource` interface, registers as "DJI Fly (LetsView)" in the source selector, and uses `mss` + `pygetwindow` for fast region capture. A source-agnostic reconnection loop in `detector.py` re-attempts the current source every second after disconnection.

Watch for: Status frames (minimized window placeholder) are fed through YOLO inference, wasting ~125ms per frame on CPU hardware for zero useful output (confirmed).

**Verdict**: APPROVED

## High-level view

All four issues from the v1 review have been addressed: reconnection loop with 1s cooldown, lock scope narrowed to geometry copy only, region-capture limitation documented, unused import removed.

Two minor concerns remain, neither blocking. The detector runs YOLO inference on status-frame placeholders (the dark "LetsView window minimized." image), burning CPU for no detection value. The `spec == "letsview://"` string comparison used to branch between `LetsViewSource` and `VideoSource` is duplicated in two places and will accumulate if more non-OpenCV sources are added, though for one additional source it's acceptable.

## Inference on status frames

When the LetsView window is minimized, `read()` returns `(True, status_frame)` — a 960x540 dark image with centered text. The detector's `_run` loop treats any `(True, frame)` return as a live frame and passes it to `annotate_frame()`. On CPU hardware running YOLOv8/v11-seg, a single inference call takes 100-200ms. At the detector's 8 FPS target, the YOLO model continuously processes placeholder images during the entire minimized period, consuming CPU for zero useful output.

The fix is lightweight: either change the return signature to include a "status" flag that the detector can check, or have `read()` return `(False, None)` for minimized (triggering the disconnect/reconnect path), or have the detector check frame dimensions before running inference.

```python
# In detector._run, after ok, frame = self._video_source.read():
if frame is not None and frame.shape == (540, 960, 3):
    # Possible status frame — skip inference, just encode and display
    ...
```

A more robust approach would be returning a named tuple or adding an `is_status` flag, but any of these prevent wasted inference cycles.

## Manual dispatch pattern

Two locations in `detector.py` contain the same branching logic:

```python
if spec == "letsview://":
    vs = LetsViewSource()
else:
    vs = VideoSource(spec)
```

This appears in both `_maybe_switch_source()` and the reconnection block. If a second non-OpenCV source is added, this pattern must be extended in both places. A factory function that maps spec prefixes to source classes would centralize the decision.
