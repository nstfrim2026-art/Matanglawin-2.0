# Dynamic network configuration and dashboard integration

Introduces `network_config.py` as the single source of truth for LAN IP detection, RTMP URL construction, and MediaMTX reachability checks. The module uses the UDP-connect trick to auto-detect the active interface, supports `MATANGLAWIN_HOST_IP` and `MATANGLAWIN_STREAM_KEY` env var overrides, and exposes a `GET /api/network` endpoint returning all connection URLs. The dashboard gains a Network Status panel showing PC IP, DJI RTMP address, and stream key, refreshed every 10 seconds. A LIVE/OFFLINE badge driven by `/status` `camera_connected` provides stream state. Tests cover IP detection, env var override, dynamic RTMP generation, the API endpoint, and a hardcoded-IP audit regex scan across all runtime `.py` files.

Watch for: The RTMP port (1935) is not checked in `check_mediamtx_reachable` despite being the most operationally relevant port for the DJI Fly workflow (confirmed). The hardcoded-IP audit in tests only scans for `192.168.x.x` patterns, missing `10.x.x.x` and `172.x.x.x` ranges (confirmed).

**Verdict**: APPROVED

## High-level view

The network configuration module centralizes all IP and URL logic into stateless functions. Every call recomputes the host IP from either the env var override or the UDP socket trick, constructs the RTMP/RTSP/WebRTC URLs, and returns them as a dict. No cached state can become stale after a network change, at the cost of redundant socket operations on every poll.

The LIVE/OFFLINE badge is driven by the existing `/status` endpoint's `camera_connected` field rather than an independent MediaMTX probe. This means "LIVE" reflects whether OpenCV can read RTSP frames, not whether RTMP ingest is active — a distinction that matters only if the RTSP path is misconfigured while RTMP is working.

`check_mediamtx_reachable` checks TCP connectivity to ports 8554 (RTSP) and 8889 (WebRTC) but omits port 1935 (RTMP). Since the primary operational question is "can DJI Fly reach my RTMP server?", this is a gap in the reachability report.

The hardcoded-IP scan in tests only matches `192.168.x.x`. Addresses like `10.0.254.31` or `172.20.10.3` that appeared in prior versions of this project would not be caught.

1. **RTMP port 1935 not checked in reachability** — `check_mediamtx_reachable` only probes ports 8554 and 8889. Add a `rtmp_reachable` check on port 1935, since this is the port DJI Fly targets and the most common failure point.

## RTMP port omission in reachability check

`check_mediamtx_reachable` in `network_config.py`:

```python
def check_mediamtx_reachable() -> dict:
    rtsp_ok = _check_tcp_port("127.0.0.1", 8554, timeout=2.0)
    webrtc_ok = _check_tcp_port("127.0.0.1", 8889, timeout=2.0)
    return {
        "rtsp_reachable": rtsp_ok,
        "webrtc_reachable": webrtc_ok,
        "mediamtx_reachable": rtsp_ok or webrtc_ok,
    }
```

Port 1935 (RTMP ingest) is the port DJI Fly connects to. If MediaMTX's RTMP listener fails to start (port conflict with another process), the user has no signal from this function. Adding `rtmp_reachable: _check_tcp_port("127.0.0.1", 1935, timeout=2.0)` completes the picture.

## Hardcoded-IP audit scope

The test regex:

```python
ip_pattern = re.compile(r"192\.168\.\d+\.\d+")
```

This project previously had `10.0.254.31` in its codebase. A more complete pattern:

```python
ip_pattern = re.compile(
    r"(?:192\.168\.\d+\.\d+|10\.\d+\.\d+\.\d+|172\.(?:1[6-9]|2\d|3[01])\.\d+\.\d+)"
)
```

## IP detection on every request

`get_host_ip()` calls `detect_lan_ip()` which opens a UDP socket on each invocation:

```python
def detect_lan_ip() -> Optional[str]:
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.connect(("8.8.8.8", 80))
    ip = s.getsockname()[0]
    s.close()
    ...
```

The 10-second poll from a single tab is negligible. Multiple tabs or additional services multiply the syscall count. A TTL cache (recompute only if last result is older than 5 seconds) eliminates redundancy while preserving IP-change detection within a bounded window.
