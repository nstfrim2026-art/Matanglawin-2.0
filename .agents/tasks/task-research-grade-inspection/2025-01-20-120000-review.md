# Research-grade inspection pipeline for UAV crack detection

This change transforms a minimal YOLO overlay script into a full Flask-based inspection system. The original main branch contained only `infer_overlay.py`, `best.pt`, and a README; this PR adds the entire web application: live video detection loop, auto-capture state machine with temporal verification and image quality gating, false-positive filtering via morphological analysis, SQLite persistence, PDF/CSV/Excel export, an inspection history page, and a real-time dashboard with summary statistics. The architecture separates concerns cleanly — video source, inference core, detector loop, capture manager, and Flask routes each live in their own module.

Watch for: The live MJPEG feed streams *raw* unannotated frames to the browser while the analysis panel relies on capture events to show overlays — users see no visual indication of detected cracks in the live feed itself (confirmed). The export endpoints (`/api/export/csv`, `/api/export/excel`) load all inspection records into memory with a hard-coded 100,000-row limit and write to `tempfile.mkdtemp()` without cleanup, leaking temporary files on every request (confirmed). The `capture_manager.py` scan logic for existing captures (`fname[5:10]`) breaks after capture 99,999 (confirmed, minor).

**Verdict**: NEEDS_CHANGES

## High-level view

The detection pipeline runs in a background thread (`Detector._run`), pulling frames from a `VideoSource` abstraction, running YOLO inference via `annotate_frame`, and storing the *raw* frame as JPEG for the MJPEG stream. This means the live feed shows no segmentation overlay — crack visibility in the browser depends entirely on the auto-capture analysis panel. A crack that appears for fewer than 5 consecutive frames is never visualized anywhere in the UI.

The capture manager implements a 5-frame temporal verification gate before triggering a background capture thread. Once triggered, the frame passes through image quality validation (blur/brightness/exposure), a second full YOLO inference pass, and a morphological false-positive filter before being persisted. Any failing gate returns to monitoring without producing a false record.

The crack validator operates without mask data in the current integration: `validate_cracks` is called with `masks=None`, so only the metadata-based geometric filters (area, length, aspect ratio) fire. The mask-based morphological checks (circularity, solidity, edge consistency) — which are the primary defense against shadow/reflection false positives — are dead code in production.

The inspection database uses SQLite with WAL mode and a module-level threading lock. Under multi-worker WSGI deployment (gunicorn), each worker gets its own lock instance providing no inter-process coordination, but WAL + `busy_timeout=5000` handles this adequately for low-concurrency workloads. The export endpoints create temporary directories that are never cleaned up, leaking files on every request.

## Raw frame streaming removes visual feedback

In `detector.py`, the MJPEG stream serves the raw camera frame:

```python
annotated, crack_present, crack_metadata = annotate_frame(
    frame, weights=self._weights, conf=self._conf, imgsz=self._imgsz,
)
# ...
jpeg_bytes = self._encode(frame)  # <-- raw frame, not annotated
```

The `annotated` result is computed but discarded for the live feed. Crack detection status is communicated only through the `/status` JSON endpoint (badge text changes to "CRACK DETECTED") and the capture analysis panel (which shows results only after the 5-frame verification + quality gate + validation pipeline completes). A crack that appears for 4 frames and disappears is never visualized anywhere in the UI.

The dashboard's "Live Detection" section heading and the live-feed visual layout imply real-time visual feedback that isn't delivered. Either stream `annotated` instead of `frame`, or provide a UI toggle between "clean feed" and "overlay feed" modes.

## Temp file leak on every export

```python
tmp_dir = tempfile.mkdtemp()
output_path = os.path.join(tmp_dir, "inspections_export.csv")
generate_full_csv_export(items, output_path)
return send_file(output_path, ...)
```

Flask's `send_file` does not delete the file after sending. Each export request leaves a file on disk indefinitely. Under automated export scripts or monitoring dashboards that periodically download exports, this fills `/tmp`. Write to a `BytesIO` buffer and serve from memory, or register an `after_this_request` callback to delete the temp directory.

## Crack validator integration gap

```python
validated_metadata = validate_cracks(analysis_metadata, raw_frame, masks=None)
```

With `masks=None`, only three metadata-based checks execute (area >= 100px, length >= 20px, aspect ratio >= 2.0). The four mask-based checks — morphological opening to reject noise, circularity to reject round blobs, solidity to reject scattered regions, and edge consistency to reject complex/noisy contours — are all skipped.

`annotate_frame` has access to the YOLO result's mask data (`result.masks.data.cpu().numpy()`) but doesn't return it. Adding the masks to the return value (or providing a separate extraction function) would activate the full validation pipeline that currently exists only as unreachable code.

## Unauthenticated state-mutating endpoints

```python
@app.route("/capture/threshold", methods=["POST"])
def capture_threshold():
    payload = request.get_json(silent=True) or {}
    threshold = payload.get("threshold")
    ...
```

On field deployment networks (shared WiFi between ground station and operators), any device can `POST /capture/threshold {"threshold": 1.0}` to effectively disable auto-capture, or `POST /capture/reset` to discard an in-progress analysis. For a research-grade system where inspection integrity matters, a simple bearer token check on mutating endpoints would prevent accidental or malicious interference without adding user-management complexity.
